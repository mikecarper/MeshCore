    Simultaneous radio2 receiver comparison, 2026-10-22

    The matched-PHY five-receiver test passed: 915.000 and 916.000 MHz, both SF7 / BW 62.5 kHz / CR4/5 (RadioLib value 5) / preamble 32. Every applicable packet arrived, and all six radios passed final preservation and session checks. The preceding mixed-PHY 915/916 campaign stopped cleanly at a case boundary under user steering; its measurements remain a separate cohort. Historical 910.525 results are not current test frequencies and are not merged into either 915 cohort.

    Latest campaign: three scanners and two fixed witnesses

    One Xiao S3 sender sent one fresh 40-packet case, with 20 primary and 20 secondary packets at preamble 32. Five receivers listen to the same physical packets concurrently. This is not separate unicast delivery to each receiver. No earlier packet is resent or replaced by this new measurement.

    Role Board Source Applicable packets per case
    Scanning receiver Heltec V3 9b70827d 20 primary + 20 secondary
    Scanning receiver Heltec V4.3 OLED 9b70827d 20 primary + 20 secondary
    Scanning receiver Heltec T096 4773ac42 20 primary + 20 secondary
    Fixed primary witness Tag 08650f64 20 primary; secondary not applicable
    Fixed secondary witness SenseCAP Indicator 08650f64 20 secondary; primary not applicable
    Sender Xiao S3 WIO ebb59d48 One direct TX per planned packet

    All six nodes matched their bound identity and full firmware version. The controller rejected a recorded saved baseline other than 915.000 MHz before opening hardware. V3 and V4 used normal firmware. The older T096 lacked the later shared RX fixes. Board hardware and firmware both differ, so this comparison cannot isolate either as a cause.

    Primary is 915.000 MHz / BW 62.5 kHz / SF7 / CR5; secondary is 916.000 MHz / BW 62.5 kHz / SF7 / CR5, both at preamble 32. Sender power is 2 dBm. The three scanners enable radio2; each fixed witness disables scanning and stays on its assigned tuple. Receiver power saving and RXPS are off. All five USB receive collectors operate concurrently. The seeded shuffled profile order uses minimum gaps after the prior physical TX_DONE confirmation; retuning can lengthen a gap. There are no RF retries or replacement packets.

    Both profiles now have the same 2.048 ms symbol duration. Scanner-derived visit policy and receive ownership still apply; matched SF/BW/preamble does not assert identical measured visits or an acquisition guarantee. This new cohort cannot be treated as another preamble-only row of the mixed-PHY test.

    The migration passed on all six radios: saved primary readback was 915.000 MHz / BW 62.5 kHz / SF7 / CR5, and each physical-apply command returned ACK 00. This confirms configuration acceptance, not an RF frequency measurement. The migration explicitly saved preamble 32; earlier effective 32-symbol status did not distinguish saved auto from explicit 32. Channels, credential hashes and all other compared saved settings were retained. No test datagrams were requested by migration.

    The new baseline was taken after migration. Cleanup must retain 915.000 and must not restore 910.525 on these radios, while preserving the other compared settings. This frequency change prevents treating earlier 910.525 data and the new 915.000 cases as one preamble-only comparison.

    Each 92-byte DEV application payload contains MCHILGR1, the sender public key, a common group digest, a fresh 16-byte nonce and a global ordinal. The digest binds all six role-ordered public keys, witness profile assignments, the campaign nonce and exact preamble/PHY/packet plan. Keys, raw identities and payload bytes are excluded from this report. Each ordinal requires one local acceptance and exactly one physical direct TX, without a flood.

    Receivers independently match exact application bytes, their owned local channel slot, DEV type and direct route. Logical profile comes from the sender ledger, not an RX-origin field in the Companion response. Queue drain, duplicates, wrong-profile witness receipts, receiver transmissions and core health are checked separately from application delivery.

    Appendix: failed attempts and restoration history

    • The preamble-32/fixed-secondary attempt retained a sender cleanup failure: restoring the original 22 dBm was rejected as radio busy, leaving test power 2 dBm. All receivers restored and V4 MQTT status recovered. The subsequent fixed-primary follow-up restored all original settings, including sender 22 dBm; that later preservation pass does not erase the failed cleanup.
    • The first longer-preamble setup stopped at T096 RXPS-off's exact radio-busy rejection under a five-second/ten-attempt configuration bound. It sent zero RF and restored all settings. A new attempt changed only safe exact-busy configuration retry to 30 seconds/40 attempts; no RF resend was introduced.
    • After the 64/128 measurements, the user-directed stop before 256 interrupted a CLI operation and original cleanup failed to clear the owned V3 channel. A separate fresh session verified its exact owned name/key digest, cleared only that record and proved full settings, channels, PIN and credentials preserved, without RF. The original cleanup failure remains retained.
    • Initial RAK4631 witness inventory failed binary framing before identity qualification. Its failed baseline was retained; the qualified Tag replaced it in the five-receiver plan.
    • The first five-receiver setup sent zero RF: V3 timed out on the first radio2-off setter after 85.74 seconds since prior I/O. V3's watch getter was unsupported, so the cause is UNRESOLVED, not confirmed idle expiry. All six nodes restored successfully. A separate final session-exit 4 KiB tail guard then failed; that failure is also retained.
    • The next five-receiver attempt was stopped immediately when the user prohibited 910.525 MHz. It is PARTIAL, not a completed four-case result. The following migration recovered the interrupted state and passed preservation of the compared settings, with the intentional saved 915.000/32-symbol setting.
