    V4 application and native USB

    The earlier 4773ac4219666d0f5b4c2bff5eb72aa053014662 application passed full readback with unchanged partition table and OTA metadata. An initial private adapter's ordinary hard reset left native S3 in forced download mode despite correct readback. The pinned flasher's masked forced-download clear and watchdog reset restored the application. Its adapter guidance was clarified in meshfirmware commit 4ce4f44; the flasher already had the correct sequence.

    The second logging-on native-console trial on 4773ac42 passed 600.1086 seconds with zero idle command writes. The observed idle phase started at 2026-10-21 00:13:03.667 UTC. First reply/reopen took 124/21.8 ms; uptime advanced 378 -> 979 -> 981 seconds. Identity, settings restoration, strict binary handback and cleanup passed, with zero core errors. However, watchdog recoveries rose from 0 to 2; the last reason was client inactivity (0x08). This is a transport PASS, not a clean watchdog qualification. The earlier browser startup failure and its successful restoration remain recorded separately.

    Fix 7278eacb9131d613da719fee814fefcdad3adf23, included in final source, requires 100 ms of continuous presence loss before invalidating the valid client lease and recognizes the host-backed physical reader. It preserves bus-reset, stall and true-unplug recovery. The finding does not conclusively attribute both earlier events to that path.
