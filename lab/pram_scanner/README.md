# W12 PRAM scanner - experimental

This scanner is a laboratory proof of concept and is not release qualified. It contains an experimental on-chip LR2021 dual-profile CAD scanner and guarded host TX handoff, plus per-received-packet internal settings snapshots. It does not change the on-air packet format. The W12 scanner cannot coexist with the Semtech vendor PRAM patch: both occupy the same PRAM. It uses the LDO regulator while active. Normal settings are restored on explicit stop/reset.

An RX-only hardware trial saw packets on both profiles with correct attribution, including independently observed primary packets. The mixed-bandwidth receive error counter increased; the secondary receiver used preamble 72 while the peer used 32. The cause and delivery rate are not yet established. TX handoff, automatic resume, new diagnostic commands and directional timing benchmark have not been qualified on hardware. An interrupt may arrive during guarded handoff; lossless operation is not established. If ownership is uncertain, the firmware briefly retains the ambiguous FIFO, then counts a possible discard and resets to host switching; scanner retry is blocked for that profile pair until changed or explicitly re-enabled. Do not use this on operational nodes.

## Provenance

The scanner derives from Alex Beal's MIT-licensed https://github.com/beala/lr2021-re, commit 20b2a85efc206eaf7bbaedcfb8b7985b0a620aab; its copyright and license are in LICENSE. scan.c, scan_hdr.S and pram.ld are the lab source; changes include guarded stop and timing command. scan-safe.bin is the corresponding image; src/helpers/radiolib/W12PramScannerBlob.h contains the same bytes as little-endian words. The exact ROM checks in the host are required; do not transplant these commands to other chip revisions.

## Rebuild and test

Run python3 lab/pram_scanner/run_tests.py with Python 3 and g++. It compiles tests in a temporary directory, verifies the guard predicate against the PRAM source, exercises host decisions and Dispatcher with actual implementation code, checks packet serialization, and verifies blob/header equality.

To regenerate PRAM, build the patched ARC GCC 13.3 Docker image from the pinned upstream repository's docker/Dockerfile.gcc, as described upstream, and use its firmware/pram/build_scan.sh with this directory's scan.c, scan_hdr.S and pram.ld. Rename resulting scan.bin to scan-safe.bin and regenerate the host header as little-endian 32-bit words; run the tests. Retain the license notice.

The scanner is included in W12 repeater, room and sensor builds and automatically starts for compatible dual-radio profiles; `set pramscan off` disables it for the current boot. A W12 Full build uses one PlatformIO process:

    PLATFORMIO_BUILD_FLAGS="-DWEBCONFIG_WIFI_CONNECT_TIMEOUT_MS=60000UL -DMESH_WIFI_ALL_CHANNEL_SCAN=1 -DMESH_WIFI_RECOVERY=1" OUTPUT_DIR=lab/pram_scanner/full-tx-final bash build.sh build-firmware meshnology_w12_repeater_observer_mqtt --full-exact --profile default --radio-preset target --firmware-version v1.18.0.2-w12-pramscan-txlab

Commands include set pramscan on, set pramscan off, get pramscan, get pramscan.last, get pramscan.diag, get pramscan.timing, set pramscan.rxpre 2 32, run pramscan.bench, and get pramscan.bench. Change receive preamble only while stopped. The benchmark measures full SPI command round trips for frequency/modulation configuration, not RF lock, full RX readiness or packet switching. Reset/recovery has different costs.

## CPU light-sleep and single-profile RXPS experiment

With `set powersaving on`, the experiment permits the existing ESP32 sleep policy to enter bounded light sleep while the PRAM scanner owns both profiles. GPIO14 is configured as an RxDone wake source. The existing policy still blocks sleep for an attached USB host, active Wi-Fi/Bluetooth, pending work, or an unavailable radio. The MCU wakes at least once per second for scanner health checks; the radio itself does not enter retention sleep between scan passes. Single-profile LR2021 hardware duty cycling is included in the same W12 builds and follows the saved RXPS setting; it remains off by default. With radio2 off, that experimental build exposes `set radio.rxps conservative` and `set radio.rxps off`. Radio2 suspends ordinary RXPS as in the existing firmware; the experimental PRAM scanner must not be active while changing RXPS.

These additions are not release qualified. Native tests cover timing arithmetic and scanner idle admission. In one controlled W12 trial, continuous RX received five of five test packets, while the initial RXPS implementation received none. After removing an SPI airtime query immediately following RXPS arm, three trials received five of five with continuous RX and five of five, 15 of 15, then five of five with RXPS; the final burst followed more than two minutes idle. RadioLib status checks and noise-floor calibration may still access the radio during duty cycling, and longer-idle and busy-channel delivery remain unqualified. Sleep residency, wireless coexistence, and current consumption have not been measured. The experimental scanner is automatic for compatible profiles; RXPS and scanner TX handoff remain unqualified. Keep the configured radio and its existing USB/network policies available while testing.

With independent power and USB data unplugged, the W12 entered ESP32 light sleep. On one profile, four successive LoRa requests each increased the GPIO-wake count and the count of radio IRQ-high observations by one. Further requests also increased those counts with LR2021 RXPS armed. With the experimental PRAM scanner and two profiles enabled, the device slept and replied on each profile; the received-packet snapshot identified the matching profile. An initial scanner image reported receive errors and timed-out secondary requests.

After setting the scanner's maximum receive length to 255, a USB-connected W12 received 20 of 20 transmitted advertisements on each profile with matching 32-symbol preambles and no host read errors. Four of five subsequent radio2 command requests received replies. A separate matching 96-symbol radio2 burst counted one of 20 before the scanner recovered from an error. After correcting timeout rounding, another USB-connected 96-symbol burst received 20 of 20 without recovery. In a later USB-unplugged run, the scanner stalled waiting for a header and its no-CAD watchdog stopped it before sleep could be verified; radio2 wake in that run remains unproven. A diagnostic build captured the ROM timer flag off at that stall. With the bounded header-timer repair, the USB-connected scanner stayed active through a 20-packet burst on each profile: it counted 20 of 20 on the 62.5 kHz primary and 19 of 20 on the 250 kHz secondary. The radio continued scanning for several minutes with no watchdog recovery; this does not establish weak-signal or long-term reliability. With the same repaired scanner, independent power, and USB unplugged, the W12 reported sleep eligible and answered on both profiles; radio2 was identified in the packet snapshot, and the GPIO/radio-high wake counters advanced on subsequent radio2 requests. The earlier build capped sleep calls near 10 ms. A later lab-only scanner ceiling allowed a sleep call near one second while preserving radio2 wake. With the saved adaptive AGC interval at 28 s, timer wakes still rose by 618 in roughly 40 s. Temporarily disabling AGC maintenance for one diagnostic interval reduced the increase to 41 in about 35 s; the original setting was restored and verified. This supports, but does not individually attribute, 50 ms AGC retries as the cause. With the lab-only one-second deferral and the original 28 s setting enabled, timer wakes increased by 64 over roughly 35 s; the scanner still replied on radio2 and recorded radio GPIO wakes. The one-second deferral does not execute or prove an AGC reset: maintenance remains pending while scanning. Actual sleep residency and power consumption were not measured. Scanner error counters cover the whole session, not just the controlled packets. Dual-profile reliability and TX handoff remain unqualified.

The lab-only `get pramscan.sleep` counts successful GPIO, timer and other CPU wakes in RAM. `radio_high` counts GPIO wakes where the radio IRQ was high when sampled; it is evidence, not proof that the radio was the only wake source. The lab-only `get radio.rxps.busy` reports sampled BUSY transitions and chip-mode observations from existing SPI transfers. Its counters reset when RXPS is armed again, and the observed mode does not prove the current duty-cycle state. `get pramscan.recovery` identifies the last scanner recovery's origin. None of these commands measures energy consumption.

While the scanner owns the radio or retains an ambiguous FIFO, a due AGC maintenance attempt is deferred by one second rather than retried every 50 ms. It is not recorded as a successful reset, and after scanner ownership ends the outstanding attempt remains scheduled. The fixed-interval path uses a strict deadline comparison, so it can retry one millisecond after that deadline; other scheduling or radio blockers can delay it further. Other radio builds retain their existing retry policy. The LR2021 wrapper's AGC reset mechanism and its effect in this scanner remain unverified; a long-running scanner can therefore defer maintenance indefinitely.

The [published W12 schematic](https://wiki.meshnology.com/assets/files/W12-MB-V0.2(1)-b62d4b0929d59c1a3c9ca5847eb65bf8.pdf) also shows LR2021 DIO7 connected to ESP32 GPIO7, in addition to the DIO8/GPIO14 interrupt already used by the firmware. GPIO7 is exposed on the expansion header, and the schematic revision must be confirmed. Mapping a preamble event there may permit activity detection without SPI, but the event is latched and can remain asserted after a false preamble; a simple high-level test or fixed-time clear is not a safe indication of current reception. No GPIO7 mapping is enabled by this experiment.
# Sequential receive-only slot experiment

The separate `MESH_W12_PRAM_SEQUENTIAL_LAB=1` build flag enables a RAM-only
experiment. It is off by default and is not a release setting. With a second
profile enabled, stop PRAM, set `radio.mode rx`, run `set pramscan.seq 1` or
`set pramscan.seq 2`, then `set pramscan on`. The selected radio visits SF5–8;
the other visits its configured SF. `get pramscan.seq` shows whether the
scanner is active or has fallen back, and `get pramscan.last` identifies the
logical radio and physical SF. Packet TX, beacon TX and carrier TX are blocked
while the experiment is selected. Stop PRAM and set `pramscan.seq off` to exit.

The lab defaults to one-symbol preamble-only CAD. Build flags
`MESH_W12_PRAM_SEQ_SYMBOLS=1|2` and `MESH_W12_PRAM_SEQ_FLAGS=0x10|0` select
the CAD length and preamble-only or any-symbol detection. SF5/6 peak values
are unverified; no RF delivery rate or 32-symbol coverage is guaranteed. The
plan rejects profiles outside the existing supported band/BW and 20 MHz span.
